# 按速度排名的任务

计时是有噪声的。同一份代码，换一台机器、换一个时刻，或者连续测两次，得到的数字都会相差几个百分点。
在一次真实的 campaign 里，同一份没有改动的成果被打分六次，结果相差超过 7%：这个幅度足以让
一个只信单次计时的搜索把已有成果的一份拷贝当成新的最好成绩，并让之后的每次会话都从它出发。

`infinievolve.task_types.perf` 放的是这类任务的所有 benchmark 都能共用的应对办法。它位于框架和单个
benchmark 的适配器之间：框架不了解任何一类任务，适配器只了解一个 benchmark。

## 分层

| 层 | 回答的问题 | 谁共用 |
|---|---|---|
| 框架（`infinievolve.core`） | 怎么搜索、保留什么 | 所有任务 |
| 任务类型（`infinievolve.task_types.perf`） | 这类结果怎么测才可信，怎么告诉 agent | 这一类的所有 benchmark |
| 适配器 | 任务从哪来、怎么评估 | 一个 benchmark 的所有任务 |
| 你的配置 | 在哪跑、以谁的身份跑 | 你自己 |

## 有哪些机制

**在框架里，适用于任何有噪声的指标**

- *复测。* 新的最好成绩会被再次打分，并按中位数排名（声明里的 `confirm`）。
- *共享测量。* 结束时成果完全相同的会话，其实是同一份成果被测了多次：它们都按全部测量的聚合值排名。
- *按请求重测。* 适配器不信任某次测量时可以说明（`SessionResult.remeasure`），这份成果会被重新打分，
  适配器能安排的话换一个地方测。
- *参考节点。* baseline 有效时是 baseline，否则是第一个有效的会话。它的成果会交给每个作业，供需要对照
  它来测量的适配器使用。

**在任务类型里，适用于计时**

| | 作用 | 默认 |
|---|---|---|
| 配对计时 | 在同一台机器上按平衡的顺序交替给候选版本和参考版本计时，按比值排名 | 开启（任务可以配对时） |
| 快照与校验 | 计时的是成果的一份私有副本；如果这份副本在计时期间变了，这次计时作废 | 开启 |
| 确定性指标 | "速度"其实是计数（指令数、字节数、操作数）的任务，既不配对也不复测 | 开启 |
| 固定硬件型号 | 在其他型号的处理器上测得的结果会被重新测量 | 关闭：写明型号即开启 |
| 机器记录 | 某台机器上的测量换地方后站不住脚，就给它记一次；记满两次不再使用 | 关闭：指定记录文件即开启 |
| 墙钟时间 | 让读取 CPU 时间的工作负载改读墙钟时间 | 关闭 |
| 清场 | 下一次计时之前，结束 agent 或上一次计时留下的进程 | 关闭：它会杀进程 |

后四项会改变被测量的东西，或者对你的机器采取动作，所以由你决定是否开启。

## 这些都不适用的情况

配对需要两个版本都能重新运行、能并排运行，而且指标本身会波动。指标是确定值时、评估无法重复时
（只读一次的留出集得分、要跑几个小时的运行）、两次运行面对的环境不同时（线上数据、外部服务），
配对都没有用武之地。这类任务最多用到框架的复测，或者什么都不用。

## 为计时类 benchmark 编写适配器

继承 `PerfAdapter`，说明你的 benchmark 是什么样的；声明和提示词措辞会随之生成。

```python
from infinievolve.task_types.perf.adapter import PerfAdapter

class MyBench(PerfAdapter):
    gate = ("correct", "in_scope")

    def pairs_with(self, task):      # 配对计时的对照对象；返回 None 表示不能配对
        return "the task's reference solution"

    def exact(self, task):           # True：指标是计数，每次都一样
        return False

    def hardware(self, task):
        return "8 CPU cores"

    # ……以及适配器接口里的作业方法
```

在 `collect` 里用 `timing_row(checks=..., speedup=..., pairing=...)` 构造每个被打分的版本。它返回评测行；
当配对各轮之间分歧过大或计时没有完成时，还会返回原因，把它作为 `remeasure` 交回即可。

测量本身在作业运行的地方执行。`measure.py` 是只用标准库的单个文件：把它和作业执行的脚本一起发送过去，
然后用两个函数调用 `run_blocks`，每个函数给其中一方计时一次。两边用同一个文件计算统计量。

[`examples/faibench`](../examples/faibench) 是按这种方式写成的一个完整适配器。
